# Course Registration System (ACSS)

## Overview

A collaborative academic project developed as part of the System Analysis and Design course (CIS 3430) during the Second Semester of the 2023–2024 academic year at the Islamic University of Madinah.

The project focuses on analyzing and designing an **Automated Course Scheduling System (ACSS)** to improve the academic scheduling process by considering the preferences of students and faculty members.

The proposed system aims to reduce the effort required for manual scheduling, minimize scheduling conflicts, and provide greater flexibility for administrators, faculty members, and students.

## Problem Statement

The traditional manual scheduling process requires faculty administrators to create course schedules without having sufficient information about faculty members' and students' preferences.

This process creates several challenges:

- Difficulty avoiding overlapping class schedules.
- Challenges in maintaining appropriate class and section sizes.
- Time-consuming manual scheduling procedures.
- Limited flexibility when modifying schedules.
- Potential dissatisfaction among students and faculty members.

## Proposed Solution

The proposed solution is an **Automated Course Scheduling System (ACSS)** that simplifies academic scheduling by incorporating faculty and student preferences.

The system aims to automate schedule generation, identify scheduling conflicts, and allow authorized users to make adjustments when necessary.

## Stakeholders

### 1. Faculty Members

- Provide preferences regarding course timing.
- Select the subjects they prefer to teach.
- Participate in the academic scheduling process.

### 2. Students

- Provide preferences regarding course timing.
- Select the courses they want to take.
- Make schedule changes during the first week.

### 3. Administrators

- Manage academic course scheduling.
- Add courses.
- Generate and modify schedules.
- Ensure scheduling requirements and constraints are considered.

## Key Features and Functional Requirements

- **Course Management:** Faculty administrators can add courses.
- **Faculty Preferences:** Faculty members can specify their preferred teaching times and course selections.
- **Student Preferences:** Students can specify their preferred course times and course selections.
- **Automated Scheduling:** Generate schedules based on faculty and student preferences, course requirements, and available resources.
- **Conflict Detection:** Identify overlapping schedules and class size limit violations.
- **Schedule Modification:** Allow administrators to modify schedules after they have been generated.
- **Student Schedule Changes:** Allow students to modify their schedules during the first week.

## Non-Functional Requirements

- **Performance:** Support varying numbers of faculty members, courses, and students as the institution grows.
- **Security:** Protect the confidentiality and integrity of faculty and student information.
- **Compatibility:** Support different devices and operating systems.
- **Maintainability:** Allow future enhancements and bug fixes without significant disruptions.
- **Usability:** Provide a user-friendly interface for administrators, faculty members, and students.

## Development Methodology

**Agile Methodology** was selected as the proposed development strategy for the ACSS project.

Agile was chosen because it supports incremental development, continuous stakeholder collaboration, and flexibility when requirements change.

Its main benefits for this project include:

- Breaking complex development tasks into smaller increments.
- Reducing technical and project risks.
- Collecting regular feedback from stakeholders.
- Adapting to changing requirements.
- Improving the system through continuous development.

## Project Objectives

The main objectives of this project are to:

1. Analyze the problems associated with manual academic scheduling.
2. Identify the system stakeholders and their requirements.
3. Define functional and non-functional requirements.
4. Apply the Agile development methodology.
5. Model the proposed system using analysis and design diagrams.
6. Design user interfaces for administrators, faculty members, and students.
7. Propose an automated approach to improve academic scheduling.

## Team Collaboration

This project was developed as an academic group project as part of the System Analysis and Design course.

It involved analyzing an existing scheduling problem, gathering system requirements, selecting a development strategy, and designing a proposed automated solution.
